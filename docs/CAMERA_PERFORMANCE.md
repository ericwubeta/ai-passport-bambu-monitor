# AI Passport 相机刷新与 FPS

日期：2026-11-10。目标为 ESP32-C3 AI Passport，8 MB Flash、无 PSRAM，ESP-IDF 5.5.3 / LVGL 9.5.0。以下实机数据采自旧分区布局。实测打印机为 X2D，局域网 TLS/6000 JPEG 源图 1920×1080，显示区 240×135。其他源尺寸仍动态计算，不固定机型。

## 同步内容

从 CYD 的 `67b6256`、`9508e50` 同步相机传输、完整预览缓存及实测 FPS；没有合入 CYD 的触摸、显示方向、引脚或供电实现。

- 复用验证过身份的 TLS／JPEG 文件会话，成功后额外等待 100ms。失败保留 5 秒退避；手动刷新可跳过等待。未经实测的 JPEG 流机型保留原来的重连／跳过缓存首帧行为。
- 后台解码为屏幕尺寸 RGB565，完整接收并校验后，短暂锁住显示并集中提交。没有源分辨率 RGB 或完整 JPEG 缓冲，没有降色深或缩小显示分辨率。
- 下方显示最近四次成功显示间隔计算的 FPS，计入取图、解码、刷屏及等待。第一张显示 `-- FPS`；距成功显示满五秒后，下一次 UI 刷新显示黄色 `Loading...` 并保留上一张有效图；恢复后显示 FPS。错误和取消不增加成功计数。
- 保留打印信息、任务名和层数布局。原亮屏／休眠状态机及 MQTT 开始／完成事件检测没有修改；空闲时仍在最后操作 30 秒后息屏，不因正在看相机而延长。

## ESP32-C3 内存适配

旧固件现场取图结束后仅约 40KB 空闲堆，不能直接增加 64,800 字节预览。C3 的指令和数据共享物理 RAM，不能把 CYD 的独立空闲 IRAM 经验直接套用。依据见 [ESP-IDF RAM 优化文档](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-guides/performance/ram-usage.html#optimizing-iram-usage)。

本分支采用以下默认设置：

| 配置 | 设置与用途 |
| --- | --- |
| `LV_USE_CLIB_MALLOC` | LVGL 使用 ESP-IDF 系统堆，取消原先预留的静态池，让未使用容量可被相机共享；没有通过缩小池容量限制其他页面 |
| `ESP_WIFI_IRAM_OPT` / `ESP_WIFI_RX_IRAM_OPT` | 关闭，将部分 WiFi 代码放回 Flash，释放 C3 共用 RAM；吞吐变化通过板上取图检查 |
| `COMPILER_OPTIMIZATION_SIZE` | 使用 `-Os` 减小代码占用；同时修正其暴露的订阅主题与 AMS 文本缓冲边界警告 |
| `FREERTOS_PLACE_FUNCTIONS_INTO_FLASH` / `RINGBUF_PLACE_FUNCTIONS_INTO_FLASH` | 将所选非 ISR 函数放到 Flash，给长时间取图保留更多连续堆；ISR 版本与 SPI ISR 的配置不变 |
| `CAMERA_BUFFERED_PREVIEW` | 开启完整预览；依赖上述分配器和 WiFi 内存设置，旧生成配置不满足时保留原条带路径 |
| `CAMERA_REUSE_SESSION` / `CAMERA_REFRESH_DELAY_MS` | 开启复用／100ms 成功后等待 |
| `CAMERA_STALE_MS` | 5000ms，可按慢机型或网络情况调大 |

预览按八行分块分配，共 64,800 字节，加分配器开销实测约 64,968 字节；另用 3,840 字节 DMA 暂存，17 次提交完成整幅画面。开始解码前检查至少还有 16 KiB 可按字节访问的空闲堆。校验失败、输入中断、内存不足、取消或拿不到显示锁时保留旧图；实际 LCD 提交中途失败才结束流显示并重绘。取图失败、离线、切页或停止后释放缓存。

LVGL 与网络共享系统堆后，需要同时观察总空闲和最大连续空闲块；仅成功分配一张图不代表所有页面和网络峰值都安全。切页压力测试曾在重建隐藏 AMS 页面时耗尽对象分配空间，回溯确认在 `lv_obj_class_create_obj` 的父对象子表扩容处写入空指针。现改为只创建当前可见详情页，离页即销毁，保留导航位置与数据，避免异步取消相机时同时重建全套详情／AMS 对象；停止确认在离开控制页时取消。原亮屏／休眠状态机没有改动。

长采样还观察到服务端 EOF 后的反复云重连。检查发现旧 MQTT client ID 仅从启动时间派生，不同板子可能产生相同 ID；现改为设备 MAC 加每次启动的随机后缀，MAC 读取失败时使用随机 ID，单次启动内重连复用同一 ID。[MQTT 3.1.1 的连接规则](https://docs.oasis-open.org/mqtt/mqtt/v3.1.1/os/mqtt-v3.1.1-os.html)要求服务器断开已存在的同 ID 客户端。本轮同时增加非 ISR 代码到 Flash 的内存余量，不能仅凭后续稳定样本断定之前 EOF 全部由 ID 碰撞或全部由内存造成。

没有改变 SPI 时钟、CPU 最高频率或原 PM 配置，没有承诺无硬件撕裂或相机连续视频能力，未测电池续航。

已有 `sdkconfig` 不会被 defaults 自动覆盖。升级时使用本分支的默认配置重新生成单独的 C3 构建配置，或在 menuconfig 中选择上述设置；保留旧分配器／WiFi IRAM 配置时，完整预览选项不会启用。配置文件重生成不会改写设备 NVS。LVGL 固定为与 CYD 共同验证过的 9.5.0，隐藏对象使用兼容的 flag API。

## 实测与边界

修改前先连续读取原固件日志，7 张成功画面的更新间隔中位数 **4.543 秒**。原固件内容与本地备份校验一致；分区、24 KiB NVS 已备份，所有刷写只更新应用分区，写后校验固件并回读 NVS。

新版第一轮在原有页面记忆和正常休眠策略下启动：**18 张成功图片**，排除前两张预热后的间隔中位数 **1.109 秒**，范围 **1.003–1.624 秒**，约 **0.9 FPS**。集中提交中位数 **17ms**，包含等锁的范围 **16–113ms**；等待显示锁时旧画面仍保留。18 张 JPEG 的 MD5 均变化，云连接建立后无断开。取图结束后空闲堆最低 **43,568 字节**、最大连续空闲块最低 **17,408 字节**、相机栈余量最低 **3,532 字节**；这些不代表整个解码／握手过程的最低值。

打印机当时处于空闲，约 30 秒自动息屏，取消正在接收的一张图并释放缓存，因此这轮只计 18 张，未把主动取消当成网络失败，也未声称完成原计划的 60 张持续采样。UI 初建时共享堆约 120,452 字节，息屏取消后约 112,524 字节。原始日志、固件与设备配置保留在本地忽略目录。

52 项主机回归通过，覆盖真实传输／解码／显示函数、完整性校验前零 LCD 提交、动态尺寸与颜色、奇数宽度拷贝边界、内存／输入／解码失败、切页取消、TLS 身份、FPS 窗口及五秒边界。新增相机异步退出时 50 轮全页面／四 AMS 导航的单页面内存约束，以及跨设备／重启的 client ID 区分。既有供电、事件亮屏与休眠回归保持通过。Passport ESP32-C3 构建通过，保留原有未使用 `SAVED_HTML` 提示。

### 修复后的切页、休眠与网络共存检查

临时诊断固件通过真实按键分发路径模拟翻页，遍历进度、监控、温度、两个实际 AMS、设备与控制页；只产生上／下翻页和 PRESS／RELEASE 活动，不执行打印控制。随后停止模拟活动，让原状态机在 30 秒后息屏，再模拟一次按键唤醒，并验证重新取图。测试源码、诊断 ELF 与原始日志均留在本地忽略目录，正式源码和构建已移除自动按键／自动切页。

修复后的最终诊断轮次成功显示 **100 张**不同 MD5 图片，98 个同一连续取图段内的间隔中位数 **1.4315 秒**，范围 **0.946–1.562 秒**，集中显示中位数 **17ms**。一轮切页取消和一次真实息屏取消分别保留记录，不作为网络失败；包含息屏／唤醒的原始最长间隔约 **9.861 秒**，没有把它混成稳态帧周期。云连接建立后 **0 次断开**，无内存错误帧、崩溃或看门狗。

这一轮图片大小中位数约 **136KB**，高于早期约 84KB；各轮实际 FPS 约 **0.7–1.0**，随图片和网络变化，不能把不同场景的数值当成固定图片 CPU 跑分，也不承诺固定 1 FPS。取图结束后的空闲堆最低 **54,016 字节**、最大连续空闲块最低 **23,552 字节**、相机栈余量最低 **3,508 字节**。额外代码迁至 Flash 后，连续内存余量也比仅启用画布的早期试验更充分。

最终已恢复无诊断注入的正式固件并写入、校验。保留正常页面记忆与 30 秒超时，45 秒观察中成功显示 **19 张**不同图片，间隔中位数 **1.022 秒**、范围 **0.951–1.643 秒**，集中显示中位数 **17ms**，随后按原规则息屏并取消在途取图。云连接建立后无断开、无崩溃，原 24 KiB NVS 刷写前后回读一致。用户确认 FPS、颜色／方向、扫屏感、其他页面与监控页来回切换及画面恢复正常。设备上不保留自动按键或强制翻页逻辑。
