# 打印状态提示音

提示音由 `main/app_mqtt.c` 在解析真实的逐台打印机状态时触发，判定逻辑位于 `main/app_notify_transition.c`。它不再依赖当前页面的刷新、开关页面或用户切换打印机。

| 前一条实际状态 | 新状态 | 提示音 |
| --- | --- | --- |
| RUNNING / PAUSE | FINISH | 完成 |
| RUNNING / PAUSE | FAILED | 失败 |
| RUNNING | PAUSE | 暂停 |
| 无历史、IDLE 或其他非打印状态 | FINISH / FAILED / PAUSE | 不播放 |
| 状态未变 | 相同状态 | 不播放 |

开机首次收到已有的“已完成”只建立基线，不重播历史完成提示。完成依据真实打印状态切换，不要求恰好接收到 99% 的进度；跳过该百分比的一次云推送仍可正确提醒。上一个实际状态在同次运行的网络重连期间保留，因此离线期间发生的完成可在重新收到 FINISH 时提醒一次。

旧问题：页面先把尚未收到数据的空状态替换为 IDLE，随后历史 FINISH 被当作新完成事件；页面级的单份历史也可能混淆不同打印机。现改为从每台打印机自己的 MQTT 状态计算事件，且仅允许上述真实状态转换。

验证：`-D NOTIFY_TRANSITION_SELFTEST=ON` 可在设备启动时运行 22 个实际 C 判定用例和独立打印机历史用例，不播放音频；正式构建关闭该选项。2026-11-07 板上自测通过，正式固件也已重新写入：恢复监控第二页后实际收到 FINISH，提示音请求为 0，相机和云连接继续工作，无断言或重启。真实新任务的物理完成与扬声器听感尚需实际打印过程验收，测试不向打印机发送控制命令。

用户随后确认重启后没有误响。真实新任务结束时的完成旋律仍需实际打印过程验收。
